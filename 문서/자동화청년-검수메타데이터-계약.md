# 자동화청년 검수 메타데이터 연결 계약

현재 발행 원장에는 콘텐츠 발행에 필요한 열만 있고, 검수표를 저장하지 않는다. 따라서 대시보드의 검수 체크와 메모는 화면을 닫으면 남지 않으며, 화면은 이를 저장된 기록처럼 표시하지 않는다.

서버 연결 시에는 콘텐츠마다 아래 한 건을 별도 저장소에서 관리한다. 기존 `발행대기` 원장의 헤더와 상태 값은 바꾸지 않는다.

- `reviewId`: 검수 기록 고유 ID
- `contentId`: 발행 원장의 콘텐츠ID
- `version`: 원문 수정마다 올리는 버전 번호
- `checks`: 9개 검수 항목의 키, AI 사전점검 상태, 사람 확인 상태, 메모
- `score`: 선택 점수. 점수만으로 자동 승인하지 않는다.
- `verdict`: `pending`, `revision`, `hold`, `approved`
- `reviewer`: 사람 검수자 ID 또는 이름
- `reviewedAt`, `updatedAt`: ISO 시각

API는 아래처럼 분리한다.

- `GET /api/threads/reviews?contentId=`: 해당 콘텐츠 검수 기록 읽기
- `PUT /api/threads/reviews/:contentId`: 검수 메타데이터 저장
- `POST /api/threads/reviews/:contentId/approve`: 서버에서 9개 사람 확인 통과와 예약시각을 재검증한 뒤에만 기존 발행 원장의 상태를 `예약됨`으로 변경

보안·운영 원칙:

- 검수 저장소는 발행 원장과 분리한다.
- 웹은 기존 발행 원장의 앞 9개 필드와 수정시각만 수정한다.
- 첫 14일은 자동 승인 기능을 제공하지 않는다. 이후에도 서버 측 검증과 사람이 정한 정책이 모두 있어야 자동 승인 여부를 검토한다.
