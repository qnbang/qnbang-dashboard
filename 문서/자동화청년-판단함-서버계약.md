# 자동화청년 판단함 서버 연결 계약

기본 화면은 AI가 올린 오늘의 판단 묶음(최대 5개)을 보여준다. 소재·실험·초안·발행·성과의 전체 목록은 보조 화면이며, 사용자는 항목별 체크리스트를 작성하지 않는다.

## 일일 배치 흐름

소재 후보 5개 → 승인된 후보 실험 → 실험 결과 5개 비교 → 발행 가치가 높은 3개 선택 → 초안·사전검수 3개 → 12·15·18시 배치 순서로 간다. 사람이 하는 일은 카드별 진행·수정·제외·보류 판단과 최종 3개 예약 승인이다.

`DecisionBatch`는 `batchId`, `brandKey`, `date`, `stage`, 최대 5개의 `items`, `recommendedIds`, `selectedIds`, `status`, `createdAt`, `updatedAt`으로 구성한다. 최종 초안 단계에서는 `slotAssignments`에 최대 3개 콘텐츠와 예약 시각을 담는다.

## 읽기 계약

`DecisionItem`은 다음 필드를 갖는다.

- `id`, `brandKey`, `stage`: 판단 항목과 단계. 단계는 `material`, `experiment`, `draft`, `publish`, `performance`만 사용한다.
- `sourceId`: 원본 소재·실험·콘텐츠·성과 기록 ID.
- `title`, `summary`, `payload`: 사람이 판단할 근거. `payload`에는 원문·링크·증거·지표·후속글 제안처럼 단계별 자료를 담는다.
- `aiChecks`: AI가 검사한 항목과 통과·주의·실패, 이유. 없으면 `null`이며 화면은 사전검수 미연결로 표시한다.
- `recommendation`, `riskLevel`, `suggestedSlot`: AI의 추천과 위험도. AI가 제안하지 않으면 빈 값으로 준다.
- `status`, `createdAt`, `updatedAt`: 판단 처리 상태와 시각.

권장 API는 `GET /api/content-decision-batches?brandKey=automation-youth&status=pending&limit=1`이다. 응답은 단일 항목이 아닌 `items` 배열을 포함한 배치다. 목록용 API는 단계별로 별도 조회한다.

## 판단 쓰기 계약

`POST /api/content-decisions/:decisionId` 본문은 아래로 고정한다.

- `decisionId`
- `action`: `approve`, `revise`, `reject`, `hold`, `continue`
- `feedback`: 선택 입력. 수정 요청이나 방향 수정에만 쓴다.
- `scheduledAt`: 최종 승인 시 선택 입력.

묶음 판단은 `POST /api/content-decision-batches/:batchId`로 보낸다. 본문에는 `batchId`, `action`, 카드별 `itemDecisions`, `selectedIds`, 최종 단계의 최대 3개 `slotAssignments`를 포함한다.

서버는 `draft` 단계의 `approve`에서만 기존 발행 원장 콘텐츠ID를 찾아 상태를 `예약됨`으로 바꾼다. 예약 시각은 필수다. 기존 발행 원장의 상태 값과 헤더는 바꾸지 않는다.

## 운영 규칙

- 첫 14일은 자동 예약하지 않는다. 게시물당 사람의 최종 승인 한 번이 필요하다.
- 이후에도 고득점·저위험·검증된 형식만 자동 예약 후보이며, 신규 형식·위험 주장·AI 검사 실패는 반드시 판단함으로 올린다.
- 판단 서버가 연결되기 전에는 가짜 판단 항목을 만들지 않는다. 기존 발행 원장의 보관함은 초안·검수 판단의 임시 대체 카드로만 읽는다.
