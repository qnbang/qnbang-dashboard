# 운영OS 전면 이관 실행표

## 목표

기존 대시보드는 과거 기록 열람용으로 남기고, `내 드라이브/큐앤뱅 뉴 대시보드`가 프로젝트·고객·할 일·수신함·일정·재무·자료 링크를 모두 운영하는 유일한 기준 공간이 된다. 기존 `큐앤뱅(공식)`은 원본을 보존하는 과거 기록 공간이다.

## 이관 단위와 완료 기준

| 단위 | 새 운영OS 위치 | 완료 기준 | 상태 |
|---|---|---|---|
| 정식 프로젝트 | `01_프로젝트/001_고객명_프로젝트명` | 파일 수·핵심 문서·원장 링크 대조, 고객ID 연결 | 준비 |
| 자체브랜드·채널 | `02_자체브랜드/브랜드명` | 브랜드 운영원장과 제작·발행·자산 경로 확인 | 7개 브랜드 파일 대조 완료, 운영원장 보강 중 |
| 실험·리서치 | `03_실험` | 계속할 것/브랜드·프로젝트 승격/보관을 결정 | 준비 |
| 고객·담당자·명함 | `04_운영원장/고객·담당자·명함 원장` | 회사·개인 중복 제거, 프로젝트 연결 확인 | 고객 24곳 이관, 담당자·명함 실제 등록 대기 |
| 프로젝트·할 일·결정·일정 | 프로젝트별 운영원장 | 개요·진행·할일·결정·일정·이력·링크 7개 탭 대조 | 프로젝트 30건·현재 할 일 23건 연결, 과거 24건 검증 대기 |
| 수신 기록 | `04_운영원장/통합수신함 원장` | 원문·채널·발신시각·고객ID·프로젝트ID 보존 | 라크 연결 완료, 메일 보관범위 승인·카카오톡봇 연결 대기 |
| 회의록 | `09_회의록` | 회의록 원문은 한 번만 저장, 프로젝트·고객에 링크 | 현재 프로젝트 회의록 5건 바로가기 연결 완료 |
| 계약·견적·매출·지출 | `05_행정` + 재무 단일원장 | 행 수·월별 합계·미수금·첨부 링크 대조 | 원본 488건 보관·실제 재무 원장 연결, 프로젝트별 계약 링크 보강 필요 |
| 교육 자료 | `06_교육` | 프로젝트 전용 자료와 공용 교육 자료 분리 확인 | 준비 |
| 공용도구 | `07_공용도구` | 실제 실행 가능, 운영체제·사용법·의존성 확인 | 350개 파일·대시보드 11개 도구 연결, 팀원 운영체제 검증 대기 |
| 개인 규칙 | `08_개인작업공간/이름` | 회사 규칙과 중복·비밀정보 여부 확인 | 신종호·김지영 공간 생성, 비밀정보 로컬 분리 유지 |

## 이관 순서

1. 기존 데이터 전체 목록을 만든다. 프로젝트 폴더, 구글 시트 탭, 대시보드 API, 자동화 입력처를 각각 한 줄씩 기록한다.
2. 고객·담당자·명함을 먼저 하나의 고객 원장으로 합치고 고객ID를 부여한다.
3. 프로젝트마다 새 번호를 부여하고, 원본을 복사해 새 프로젝트 폴더와 운영원장을 만든다. 프로젝트별 파일·문서·회의 링크를 원장에 넣는다.
4. 할 일·결정·일정·수신 기록을 프로젝트ID와 고객ID 기준으로 연결한다. 중복은 원본 링크 하나를 남기고 합친다.
5. 계약·매출·지출·인건비를 월별로 대조한다. 금액이 한 건이라도 다르면 이관 완료로 표시하지 않는다.
6. 라크·메일·카카오톡·캘린더·통장 입력을 새 수신함 후보에 보내고, 사람 확인 뒤 새 원장에 기록되게 바꾼다.
7. 새 대시보드가 모든 원장을 읽고 새 프로젝트·명함·할 일을 실제로 등록할 수 있는지 확인한다.
8. 기존 대시보드는 과거 기록 화면으로 고정한다. 원본은 삭제하지 않고, 새 기록 입력만 막는다.

## 다른 맥북에서 해야 할 작업

| 대상 | 해야 할 일 | 완료 판단 |
|---|---|---|
| 카카오톡봇 맥북 | 현재 실행 폴더·시작 방식·로그 위치를 확인하고, 원문·발신시각·대화ID·첨부 링크를 GCP 수신 주소로 보내게 수정 | 테스트 메시지 1건이 새 운영OS 통합수신함에 중복 없이 표시됨 |
| 카카오뱅크 문자 맥 | 기존 문자 읽기 자동화가 보내는 주소와 인증값을 확인하고, 새 재무 확인 원장에도 후보로 전달 | 입금 1건이 자동분류 후보로 표시되고 사람 확인 전에는 금액 원장을 바꾸지 않음 |
| 팀원 맥·윈도우 | 구글 드라이브 데스크톱을 공식 폴더에 연결하고, `07_공용도구`의 실행 가능 도구를 각 운영체제에서 점검 | 같은 폴더와 같은 최신 파일이 보이고, 도구별 실행 결과가 기록됨 |

## 이관 중 금지

- 원본 확인 전에 삭제·이름 변경·대량 이동하지 않는다.
- 기존 재무 원장과 새 재무 원장에 동시에 확정 금액을 쓰지 않는다.
- 대시보드 화면용으로 파일이나 회의록을 복사해 두지 않는다.
- 카카오톡·메일 원문을 요약문만 남기고 버리지 않는다.
- 새 프로젝트 생성에 기존 날짜 폴더 생성 자동화를 재사용하지 않는다. 새 운영OS 번호 발급 규칙을 별도로 적용한다.

## 재무 자료 이관 기준

- 원본 파일은 `05_행정/재무` 한 곳에만 보관한다. 월별 폴더와 별도 확인 원장은 만들지 않는다.
- 금액·납부·지급 상태는 기존 재무 원장 엑셀 하나만 사용한다. 새 대시보드는 원본 파일을 연결해 보여주되 같은 항목을 별도 완료 처리하지 않는다.
